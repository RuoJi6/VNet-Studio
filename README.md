# VNet Studio 0.10.6

macOS 上的 Tauri 2 + Vue 3 图形化工具，用来管理 Parallels 内的 Windows、Linux 和 macOS 虚拟机。桌面应用目前只构建了 macOS Apple Silicon 版本；这里的跨系统支持指来宾操作系统。

## 0.10.6：连接日志分页

端口转发与 SOCKS5 规则的连接日志默认每页 10 条，可选择 20 或 50 条，并通过首页、上一页、下一页和末页浏览。分页栏显示当前范围与页码。历史页保持浏览快照，五秒自动刷新不会打乱记录；有更新时可点击“回到最新”。切换规则重置分页，空记录显示明确提示。同时修复日志页签被撑成竖向长条的问题。分页针对后台返回的最近日志（Mac 与 Linux 后台最多保留最近 200 条），不表示完整归档检索。

## 0.10.5：整体拓扑、服务流向与操作入口

默认“整体拓扑”同时显示宿主机、网卡、虚拟机和运行中的转发 / 代理。服务入口紧邻实际运行机器，并以蓝色 TCP 或紫色 SOCKS5 箭头连接已知目标机器；外部或未定位的目标单列展示。灰色曲线表示网络配置归属，灰色虚线表示服务运行归属。Mac 本地入口不再被放在虚拟机后面，也不会用一条无含义的长线穿过中间卡片。

“服务流向”提供访问来源 → 转发 / 代理入口 → 实际目标的简明视图，“访问权限”保留允许、未允许及待确认来源。没有活动目标的 SOCKS5 明确等待客户端指定目标。箭头表示配置方向，不保证连通；不推测 VPN 实际流量路径。

拓扑上方可选择操作对象，再进入“新建端口转发”“新建 SOCKS5 代理”“配置 VPN”。点击机器节点切换操作对象；Mac 支持本地 TCP 转发，SOCKS5 与已有 VPN 配置在虚拟机内管理。导航不会自动开启服务或连接 VPN。

连线使用平滑曲线，受到卡片阻挡时采用带圆角的避障路径。节点拖动、路线高亮、触摸板缩放和平移保持可用。选择服务仅聚焦该服务的运行机器与目标，避免代理回路把整个网络都高亮。

## 0.10.4：目标地址与连接错误说明

Mac 本地转发填写回环目标时明确标出“当前目标是本地 Mac”，关联虚拟机不改变目标地址。可点击“改用虚拟机地址”使用所选机器的已知私网 IP，保留用户填写的服务端口，不自动改写或开启规则。

连接被拒绝、超时、路由和权限问题分别显示对应说明。错误 61 不再附加错误 65 的权限建议；权限快捷按钮只根据实际连接错误显示，不匹配目标端口数字或旧后台附加的说明。

## 0.10.3：触摸板缩放

网络拓扑支持 Mac 触摸板双指捏合缩放，以手势位置为中心，范围 40%–200%。双指滑动仍用于滚动画布，节点拖动与路线高亮在缩放后保留。缩放按钮以画布中心缩放。桌面 WebKit 手势和浏览器预览的 Ctrl+滚轮事件分别适配，仅在拓扑画布内接管缩放。

## 0.10.2：拓扑拖动与节点关联路线

可拖动节点调整布局，拖动画布空白区域平移视图；刷新数据保留当前节点位置。“重置布局”恢复当前视图的初始位置。点击机器或网卡会高亮其上游与下游关联路线，点击具体连线则聚焦该线；Esc、点击空白或“取消高亮”恢复。节点和连线标签加大间距。

## 0.10.1：拓扑对比度与系统图标

拓扑使用更深的连线、标签与卡片边框，默认以 100% 显示。选中路线显示橙色连线及两端卡片，其他连线保留 80% 不透明度。Mac、Ubuntu、Debian、Kali 与 Windows 使用各自的系统标志，机器列表、虚拟机选择器与拓扑保持一致；网卡使用 Wi-Fi、网桥、回环和以太网图标。系统类型优先依据 Parallels 的 OS 字段，无法识别时保留通用图标。状态以文字和彩色标记同时显示，不将挂起状态误标为运行。

图标随应用打包，离线可用；来源和许可证见 `desktop/src/assets/machines/SOURCES.md`。仅调整展示，不更改转发、路由、虚拟机或权限配置。

## 0.10.0：DBX 风格桌面界面

主界面迁移到 Tauri 2 + Vue 3 + TypeScript，使用 shadcn-vue 的 reka-nova 组件、Tailwind CSS 4、Geist 字体与 Lucide 图标，参考 [DBX](https://github.com/t8y2/dbx) 的中性色、32px 控件与来源/目标双栏布局。字体与前端资源随应用打包；发行版通过 Tauri IPC 调用随包 Rust CLI，不依赖开发服务器。

入口与目标分别显示运行位置，端口和目标地址初始为空。Mac / 虚拟机、端口转发 / SOCKS5 的输入分别保留；来源主机可单选、多选、自定义或选择全部，不默认全放行。配置不会自动开启。

构建 Apple Silicon 桌面包（需要 Node.js、pnpm、Rust 与 Xcode Command Line Tools）：

```sh
git clone https://github.com/RuoJi6/VNet-Studio.git
cd VNet-Studio
./build-desktop.sh
```

产物为上一级 `VNet Studio.app`。前端在 `desktop/src`，Tauri 桥接在 `desktop/src-tauri`，共享管理逻辑与 CLI 在 `src`。原 egui 界面保留为兼容开发入口，不再用于发行包。

升级时检测 Mac 后台的可执行文件版本；旧后台不会自动中断运行规则。停止所有 Mac 规则后可点击“重启空闲后台”，配置保留。

错误 `No route to host (os error 65)` 表示 Mac 到实际目标的 TCP 连接未建立；可能涉及目标地址、路由、VPN/TUN、防火墙或 macOS 本地网络权限，不能只凭此错误确定原因。CLI 可达也不能证明 GUI 应用已获本地网络权限。失败时不留下新监听入口，可从错误提示打开系统权限页后重试。升级后 macOS 可能短暂缓存旧应用 UUID；错误 65 的预检查最多重试三次，总时限仍为三秒，不自动修改权限。

## 0.9.0：Mac 本地转发入口

端口转发新增「监听位置」：**本地 Mac 上运行 / 所选虚拟机内运行**。表单明确区分入口 IP、入口端口、实际服务地址，并显示完整链路。

| 运行位置 | 浏览器访问入口 | 转发程序在哪里 | 实际服务地址如何填写 |
|---|---|---|---|
| 本地 Mac | `http://127.0.0.1:18787` | 本地 Mac | Kali 服务填 `10.211.55.18:8787`；`127.0.0.1` 指 Mac 自己 |
| 所选虚拟机 | `http://10.211.55.18:18117` | Kali 虚拟机内部 | Kali 自己的服务可填 `127.0.0.1:8787`；此处回环地址属于 Kali |

Mac 本地模式默认回环 IP `127.0.0.1`；入口端口和实际服务地址由用户明确填写，两个运行位置分别保留输入，不预填测试业务端口或目标。仅接受 `127.0.0.0/8` 回环监听，供本机程序访问。可以新增、批量新增及独立开启、停止、删除多条规则；停止保留配置，删除停止现有连接并移除配置。全部 Mac 规则独立于所选虚拟机显示，即使没有选择 VM 或 VM 已挂起，也能停止和删除 Mac 入口。VM 选择只用于填入实际目标，不会将转发程序放进 VM。

开启前实际绑定入口检查占用，并从 Mac 连接目标做 TCP 检查。目标不可达时释放入口，不保存新的半成品配置。已经保存的规则开启失败仍保持停止状态。支持链路检查，显示目标 TCP 结果与 Mac 路由；监听成功和 TCP 成功不代表网页、TLS 或应用请求成功。

「转发与代理监控」分区显示 **宿主机 Mac · 本地转发入口** 与 **所选虚拟机 · 虚拟机内转发与代理**；每条规则显示运行位置、实际目标、连接数，支持复制网址、打开入口、查看连接日志。网络拓扑中 Mac 服务归属于 Mac，回环来源只属于本机，不会被判定为其他 VM 可访问。

本地后端使用 Rust 原生 TCP，不要求 Mac 安装 Python。后台程序关闭 GUI 后继续运行；Mac 重启/后端退出后，配置保留且不会自动开启。规则、控制通道及轮转日志保存在当前用户的 `~/.vnetstudio-host`（目录 0700，文件/Unix socket 0600）。控制操作不按 PID 杀进程。每条服务最多 128 个并发连接，最多 128 条规则；内存保留最近 200 条事件，磁盘每条规则约 2 MiB。仅记录连接元数据，不记录报文、URL 或密码；重启后可读取历史事件，字节统计按本次后端进程累计。

本地入口让浏览器连接 localhost，但后续 **Mac → Kali** 仍遵循 Mac 当前路由，可能受 VPN/TUN、系统代理或应用重定向影响。工具不修改 VPN 客户端、系统代理或系统路由。当前现场路由和浏览器验证结果见应用旁的 `Mac本地入口实测.md`；不能将当前成功外推为所有 VPN/TUN 配置都能绕过。

CLI 示例（无须 `--prlctl` 或来宾执行通道）：

```sh
vnetctl-cli host-forward add --listen 127.0.0.1:18787 --target 10.211.55.18:8787 --vm 'Kali Linux 2026.1'
vnetctl-cli host-forward list
vnetctl-cli host-forward check --listen 127.0.0.1:18787
vnetctl-cli host-forward stop --listen 127.0.0.1:18787
vnetctl-cli host-forward start --listen 127.0.0.1:18787
vnetctl-cli host-forward delete --listen 127.0.0.1:18787
```

## 0.8.2：点击路线高亮

网络拓扑与「谁能访问」均支持直接点击曲线或连线标签：选中路线变为橙色粗线，两端节点同步突出，其他连线淡化。鼠标悬停显示路线两端和关系说明；虚线空隙也可点击。选择按曲线距离判断，不按整块包围框，降低交叉区域误选。

点击空白、按 Esc 或点击「取消高亮」恢复；点击节点切回节点选择。刷新后已消失的连线自动取消选择。高亮不改变原有虚线 / 实线语义，不执行网络配置，不代表网络连通或访问已允许。

## 0.8.1：访问来源单选、多选与全部来源

转发与 SOCKS5 表单的「允许谁使用此入口」支持单选主机、多选主机、全部来源，以及自定义逗号分隔的 IPv4/CIDR。点击「刷新来源列表」读取宿主机和运行中虚拟机的地址；选择主机会保存其当前已知私网 IPv4 的 `/32` 集合。规则按连接源 IP 匹配，不绑定虚拟机身份；IP 变化后需更新。

「全部来源」使用 `0.0.0.0/0`，允许所有能到达当前私网监听入口的 IPv4 来源。它不改变监听接口、路由，不自动建立公网映射。清空选择会阻止创建，不会默认为全部；升级不会改变任何已运行规则。调整现有规则仍需先停止，再按新的来源添加并开启。

Unix 辅助进程逐连接匹配任一所选网段；Windows 防火墙写入多个 RemoteAddress 或 Any，读取时还原多来源规则。拓扑按相同的并集规则判断每个已知来源；“允许”仍不代表实际路由和其他防火墙已连通。Windows/macOS 来宾本次未做端到端实测。

实测：从 Mac 与 Kali 分别验证仅宿主机、仅 Kali、Mac＋Kali 多选、全部来源四种范围；TCP 转发与 SOCKS5 共 8 组均符合允许 / 拒绝预期。界面已验证单选、多选、全部切换及清空全放行规则。临时服务和规则已清理，40 项 Rust 与 26 项 Python 测试通过。

## 0.8.0：多规则管理与直接启停删除

端口转发和 SOCKS5 页面同时展示新增表单与当前虚拟机的规则列表；监控页合并展示两类规则。每条规则可以直接开启、停止、删除，不再预览确认。停止保留目标与来源限制供重新开启；删除会停止服务并移除规则，Unix 历史日志文件仍保留。非本工具管理的规则保持只读。

勾选「批量添加」可一次添加最多 128 条。转发每行填写 `监听端口 目标IPv4:端口 [允许来源网段]`，代理每行填写 `代理端口 [允许来源网段]`；省略来源时使用表单来源。所有行先校验；执行期间遇到失败则保留已成功规则，报告失败行与后续未执行行，不会覆盖已有监听。

切换页面不再显示上一页的路由输出；服务没有运行或正在读取时，拓扑保留网络连接并显示说明。Windows 新增保存规则功能，停止后可重新开启；Windows 与 macOS 来宾本次未做端到端实测。

实测验证：Mac 通过 Ubuntu 测试虚拟机的两条 TCP 转发和两条 SOCKS5 代理取得 HTTP 200；验证逐条停止、重新开启、删除运行中 / 已停止规则、其他规则不受影响、批量预校验及部分失败报告。GUI 已检查多规则列表、直接停止一条测试规则，以及无运行服务时保留网络拓扑；临时服务与规则已清理。38 项 Rust 与 25 项 Python 测试通过。

## 0.7.0：活动服务拓扑与访问范围

- 「网络拓扑」读取正在运行的虚拟机，显示检测到的 TCP 转发、SOCKS5 监听入口、连接数及目标。固定转发目标表示配置；新 Unix 辅助进程通过当前活跃连接表报告 SOCKS5 目标，断开后不再绘制，历史事件不会误判为当前连接。
- 勾选「访问范围视图」，按 **来源主机 → 服务入口 → 目标** 展示。点击一个服务聚焦其关系；选中节点下方表格列出宿主机及运行中虚拟机的已知 IPv4、规则判断与匹配地址。规则判断不等于连通测试；没有来源数据或无法解析访问规则时显示待确认。
- 服务卡片显示允许的 IPv4/CIDR、运行所在虚拟机和活跃连接数；目标中的 `127.0.0.1` 指代理所在虚拟机本身，Mac 应访问转发入口，不应直接访问这个目标地址。
- 双击服务或目标节点打开对应服务的日志；选中节点后可直接停止，停止后刷新移除节点，历史日志仍保留。读取失败有明确提示，超过 30 秒的服务快照以灰色显示，可手动或每 10 秒刷新。
- 新建转发 / SOCKS5 时可选宿主机某个源 IP，或某台虚拟机的源 IP（`/32`），也可填写多个逗号分隔的私网 CIDR，或选择全部来源。地址来源为当前宿主机接口及 PD 报告，连接实际使用的源地址由路由 / NAT 决定；来源控制按 IP，不绑定虚拟机身份。
- 对现有服务，选中节点 →「按此配置调整访问范围」会带入其监听、目标和规则；先停止，再选择新来源，点击添加并开启。这会中断此服务的现有连接。不会自动扩大已有服务权限。
- Windows 读取工具创建的防火墙允许规则；支持多地址，未知符号范围不做访问结论，其他防火墙规则仍可能影响实际结果。Windows / macOS 来宾本次未做端到端实测。Unix 仅发现本工具执行用户管理的服务，不扫描任意进程。
- 升级前已运行的 Unix 服务不会自动重启；若未提供 SOCKS5 活跃目标遥测，仍显示入口并明确提示缺少目标信息。

实测：Mac 通过临时转发和 SOCKS5 访问 Ubuntu 测试虚拟机内的 HTTP 服务；活跃目标随连接建立与断开出现 / 消失。分别配置宿主机专用与 Kali 专用 `/32`，验证两个来源的允许和拒绝行为，以及停止后立即重建。35 项 Rust、22 项 Python 测试通过。详情见应用旁的 `topology-access-test.json`、`topology-live-test.json` 和 `拓扑与访问范围实测.md`。

## 0.6.0：默认出口与指定路由

在左侧「默认出口与路由」页，或拓扑节点的同名操作中：

1. 读取所选来宾的实际网卡、IPv4、默认路由和 DNS；从网卡下拉列表选择出口，已有默认网关会自动带入。
2. 「预览设为默认 IPv4 出口」将精确列出移除的默认路由与新默认路由。应用后重新读取内核路由表核对。
3. 填写单个 IPv4 或 CIDR，例如 `192.168.10.117`（规范化为 `/32`）或 `192.168.10.0/24`，指定所选网卡和下一跳。网关必须在该网卡的直连网段；仅直连目标允许留空。已有相同目标前缀时不会自动覆盖。
4. 可精确删除指定前缀的路由，不能删除系统直连或不支持的复杂路由。界面会列出所有将被删除的同前缀条目。
5. 「查询出口网卡」调用系统路由查询，不向目标发送探测包。它验证出口选择，不表示目标服务或互联网可达。
6. 支持撤销上一次成功变更；若涉及的路由被其他程序修改或来宾已重启，会拒绝自动撤销。执行命令失败会尝试恢复已移除的路由，恢复失败会明确显示；写操作前的恢复记录保存在来宾状态目录。

所有变更仅在当前运行期间有效：Linux 操作 IPv4 main 表，Windows 操作 ActiveStore，macOS 操作非接口作用域的可管理 IPv4 路由。不改 DNS、IPv6、DHCP/NetworkManager 配置、持久化路由或 VPN 策略。DHCP/VPN/网卡重连可能覆盖配置；更具体的 VPN 路由、策略路由和应用绑定接口仍可能改变出口。

Linux 路由后端已经在测试虚拟机的独立网络命名空间中用两张 dummy 网卡实际验证默认出口切换、`/24` 分流、`/32` 优先、内核查询、过期预览拦截、删除及撤销，测试空间已清理。没有更改虚拟机主网络默认路由。macOS 在宿主机完成只读解析验证；Windows 与 macOS 来宾写操作尚未实测。Rust 30 项和 Python 20 项测试通过。原始验证记录在应用旁的 `routes-integration-test.json`。

实现参考：[Linux ip-route 手册](https://man7.org/linux/man-pages/man8/ip-route.8.html)、[Microsoft New-NetRoute](https://learn.microsoft.com/en-us/powershell/module/nettcpip/new-netroute)，macOS 参数按本机 `/usr/share/man/man8/route.8` 核对。

## 使用

双击旁边的 **VNet Studio.app**。升级后退出旧窗口并重新打开。

1. 在网络概览中查看所有虚拟机的系统、运行/挂起/停止状态和 Tools 状态。
2. 选择已启动的虚拟机，点击「读取状态」。确认虚拟机共享网卡的 IPv4 地址。
3. 进入端口转发页先选择运行位置。Mac 本地模式填写本机入口和虚拟机的实际服务地址；虚拟机模式及 SOCKS5 填写虚拟机入口和允许来源。
4. 点击「添加并开启」，在下方列表中管理多条规则。服务只使用你指定的虚拟机，不会自动唤醒其他虚拟机。
5. 「容器状态」页读取所选虚拟机的 Docker/Podman 容器，显示引擎、名称、镜像、状态和端口，并统计运行中数量。包含已停止的容器。列表按刷新时刻读取。

虚拟机和 Docker 容器是不同层级：概览列出 Parallels 虚拟机；容器页列出该虚拟机内当前 CLI 上下文可见的 Docker/Podman 容器。没有安装引擎、权限不足或守护进程不可用时，会显示具体错误，不会自动启动 Docker 或容器。

## 系统支持

| 功能 | Windows | Linux | macOS 来宾 |
|---|---|---|---|
| 网络状态 | PowerShell 网卡/路由 | ip / ss | ifconfig / netstat |
| TCP 转发 | netsh portproxy | 来宾辅助程序 | 来宾辅助程序 |
| SOCKS5 | 已安装的 GOST v3 | 来宾辅助程序 | 来宾辅助程序 |
| 已有 VPN | rasdial | NetworkManager / nmcli | scutil --nc |
| 容器列表 | Docker / Podman | Docker / Podman | Docker / Podman |

所有来宾都需要可用的 Parallels 命令执行通道。`possibly_installed` 不能证明 Tools 服务正在运行。macOS 来宾如果其 Parallels 版本不支持命令执行，该通道仍会报错；本工具没有 SSH 备用通道。

Linux/macOS 辅助程序使用系统 **Python 3.9+** 标准库，通过 prlctl 标准输入运行；不需要 GOST，不会下载软件或使用 sudo。Python 不存在时需要自行安装。GUI 与后端管理程序是 Rust，Unix 来宾网络辅助程序是 Python。

Linux VPN 功能要求 NetworkManager；只允许对 VPN/WireGuard 类型的已有连接进行操作。macOS VPN 仅覆盖 scutil 可控制的连接，不包括所有第三方 VPN。凭据需在来宾原工具中配置，本工具不保存密码。

## 网络与生命周期

- 在虚拟机内运行时，监听 IP 必须是所选虚拟机实际拥有的私网地址。Windows 和 Ubuntu 的 IP 常常不同，不能直接照抄。
- 允许来源默认 `10.211.55.2/32`，这是本机示例中的 Mac 共享接口地址。需要其他虚拟机访问时，可填写实际共享网段，例如 `10.211.55.0/24`。
- Unix 辅助程序逐连接验证来源网段，最多同时处理 128 个连接，不修改系统防火墙。若来宾防火墙阻止监听端口，需要按实际策略放行。
- SOCKS5 无用户名密码认证。Unix 支持 TCP CONNECT、IPv4/IPv6 目标和代理端域名解析；不支持 UDP ASSOCIATE/BIND。TCP 转发不是完整 VPN 转发，不包含 GRE/IPsec。
- 代理遵循来宾现有路由。先确认目标能在来宾内访问。VPN 切换会影响路由，本工具不会自动修改路由。
- Linux/macOS 的服务后台运行，关闭 GUI 后仍保留；从对应页面停止。服务不自动启动，来宾重启后可从保存的规则重新开启。
- Unix 状态位于执行用户的 `~/.vnetstudio`，使用权限为 0700 的目录、0600 控制套接字与随机控制令牌；停止操作不会按未知 PID 杀进程。异常退出的残留状态会拒绝覆盖，需确认服务已停止后处理相应残留文件。
- Windows TCP 转发及防火墙规则持久保留，GOST 不设开机自启。
- 只删除本工具创建的配置。之前手动配置的 Windows 转发可以查看，但不会被直接接管、覆盖或删除。

```sh
cargo test --locked --bin vnetctl-cli
python3 -m unittest discover -s guest -p 'test_*.py'
```

`build-desktop.sh` 会构建 Tauri 桌面前端及 Rust CLI，并在项目上一级生成 `VNet Studio.app`。应用内的 `vnetctl` 是 Tauri GUI，`vnetctl-cli` 是同目录管理后端；根 Cargo 工程还保留旧版 egui 界面源码。应用包包含两者；不需要在 Mac 上安装 Python 来运行 GUI（Unix 来宾需要 Python）。

## 0.3.0：IP 选择与宿主网络管理

- 端口转发与 SOCKS5 页的监听 IP 支持下拉搜索（IP / 网卡名），也可手动输入。PD 报告的私网地址会作为候选；「读取网卡 IP」通过 Tools 获取来宾地址。切换 VM 会清空上一台的 IP 与执行详情。监听地址须可从 Mac 到达。
- 「本机与虚拟机网络」显示 Mac 物理/虚拟接口的链路、IPv4、桥接到的 VM，及 PD 虚拟网卡配置。点击「刷新网络 / USB」更新设备插拔状态；不进行后台轮询。
- 选择 VM 和虚拟网卡，可以切换共享 NAT、桥接、仅主机模式，新增网卡，连接/断开网线，启用/禁用网卡。桥接列表只列 PD 实际报告可桥接的接口。此页面通过宿主 PD 控制网卡，不依赖来宾 Python 或 Tools。挂起/暂停的 VM 需先在 PD 恢复或关闭。
- USB 设备支持搜索、当前连接状态、即时连接到所选运行中 VM、从所选 VM 释放，以及下次插入时归属 VM / Mac / 询问。历史设备显示「未插入」，可设置未来归属，但不能即时连接。已有连接的设备需先从原 VM 释放。
- USB 独占直通会使 Mac 无法同时使用该设备；桥接则保留设备在 Mac 上。USB 兼容性取决于 PD 与来宾驱动。macOS 来宾的 USB 永久分配及仅主机模式在本界面中受限，当前环境没有 macOS 来宾可实测。
- 每次修改均先读取真实状态，生成具体 VM、网卡/USB 和命令预览。点击应用时重新核对状态，配置变化会使预览失效。命令成功后重新读取设备状态。命令失败不显示成功，也不自动重试写入。

### USB 有线内网 + Wi-Fi 外网

1. 选择 VM，保留其原有「共享网络（NAT）」网卡。
2. 把 USB 有线网卡插入 Mac，并选择让 Mac 使用它。
3. 刷新网络，选择「桥接网络」和该 USB 物理接口，点击「预览新增网卡」后应用。
4. 在来宾中按比赛网络要求设置新增网卡的 IP、网关和路由。共享 NAT 使用 Mac 的默认网络出口，并不独立绑定 Wi-Fi。

若需要 USB 设备由 VM 独占，可改用 USB 区域的即时连接/归属功能。工具不自动修改 Mac 服务优先级、静态 IP、DNS 或来宾路由。

宿主网络 CLI：`vnetctl-cli host-network list`；`host-network preview --request JSON` 返回带状态快照的计划，`host-network apply --request PLAN_JSON` 在重验后应用。可用 `--prlctl /usr/local/bin/prlctl` 指定 PD CLI。
